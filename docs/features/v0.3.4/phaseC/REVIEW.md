# Phase C — physical recovery and atomic identified receipts

All receipt calls now require an explicit expected pending identity, including legacy zero. Physical player/manager cargo uses its captured visual identity; immediate virtual/legacy paths pass the current pending identity. Wholesale additionally requires its player-unloaded checkpoint. Mixed lines, arithmetic, capacity and selected pallet validate before mutation. Final stock, supplier liability, provenance, cleared pending order and optional last outcome share the existing complete atomic save; failure restores the previous outcome and accounting.

Additive SupplierOutcomeV1 stores one terminal receipt/cancellation, not an independent inventory ledger: Version=1, State (0 absent/1 received/2 cancelled), OrderTicks, Cost, Invoice, ActiveMs, Supplier, Pallet (-1 when no physical slot), Prepaid, Line0-3. Absent/invalid optional history means unknown, without discarding valid pending cargo. Existing SupplierOrderV1, FinanceV1, RepairPromisesV1, saved placements and stock keys retain meanings. Invoice is accrued liability, not cash paid. Prepaid cancellation refunds once with overflow checks. Old history is not fabricated. Rollback uses a matching complete business-data backup and script; do not alternate builds against a modified sole save.

Driver exit now has one ordinary leave task, one fallback after 25 active seconds, confirmed on-foot state before rear unloading, and recovery after 40 seconds. Rear package creation requires reaching the rear rather than merely waiting 16 seconds; the existing 45-second rear-stage recovery remains. Driver/crate/pallet entity limits unchanged. This is a source-grounded bounded recovery correction, not a proven fix of all GTA stalls or crashes.

Wholesale load/unload and manual recovery now save-or-rollback their cargo checkpoints before finalizing visual ownership. Pallet purchase now rolls back cash/spend/ownership on failed save before deleting visuals. Existing reload behavior remains: carried/unloaded wholesale cargo returns to warehouse recovery after reload, retaining original order, not automatically respawning a box into the player's hand. No manager warehouse pickup. No earned box deletion or count reset to resolve visual capacity.

Actual checks: original supplier 37/37, cart 32/32, review 12/12, and new receipt/checkpoint/history/exit/atomic file helper 32/32; Release zero errors/two inherited warnings. Existing adapter tests were updated to call the now-required identity parameter and include the new metadata type; assertions were retained. Final combined suites follow. Real engine physics, native attachments, interrupted game process and Enhanced runtime remain owner QA.
